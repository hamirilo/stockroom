# 種類で絞る：サイドバーの範囲

**実装済み**（下の「実装で決めたこと」）。モック（3 案）を比べて、C（サイドバー上部の 1 行のメニュー）にした。

今の種類は画像と動画だけ（ファイル・テキスト・ブックマークは外した。[FILE_APP.md](FILE_APP.md)）。下の「困っていること」「比べた案」は、5 種類あったときのもの。
**2026-11-22：2 種類になったので、メニューをやめて［画像｜動画］のセグメントにした**（下の「決定」はセグメントに合わせて直した）。

使っていて困っていること：

- 最初は画像・動画を管理するアプリとして作り、あとからファイル・テキスト・ブックマークを足した。そのため、今はいろいろな種類が 1 つの一覧に混ざっている
- 種類を選べるのは絞り込みの行の「種類」のチップだけ。評価やタグのような使い捨ての条件と同じ並びにあるので、「ファイルだけを見たい」ときに探しにくい
- 「種類」は場所（フォルダ・タグ）を移っても残る（[NAVIGATION.md](NAVIGATION.md)）。ほかの条件と動きが違うのに、見た目は同じチップ
- サイドバーの件数は種類に関係なく全部を数えるので、「このフォルダに画像がいくつあるか」が分からない

## 決定

種類は「その中をどう絞るか」（絞り込み）ではなく **「何を見ているか」の範囲** として扱い、サイドバーに置く。

| 論点 | 決定 |
|---|---|
| 置き場所 | サイドバー上部に **［画像｜動画］のセグメント** を 1 行で置く（2026-11-22。それまでは 1 行のメニューボタン）。絞り込みの行の「種類」のチップは無くす |
| フォルダと同じ「場所」にしない理由 | 場所は 1 つだけ選ぶもの（[NAVIGATION.md](NAVIGATION.md)）。種類を場所と同じ並びにすると、押した時点でフォルダから抜けてしまい、「このフォルダの画像だけ」が見られなくなる。範囲は場所と別の段に置き、組み合わせて使う |
| 「すべて」の扱い | 種類の側には **「すべて」を置かない**。何も選んでいなければすべての種類を出す。「すべて」という言葉は、サイドバーの場所の「すべて」だけに残す（2 つあると意味が伝わりにくい） |
| セグメントの表示 | 種類ごとにアイコン・名前・件数。何も押していなければどちらも押されていない見た目で、両方を出す。押した方が `thumb` の面になる。件数は **今開いている場所の中で** 数える |
| 選び方 | 押した種類だけにする。押している方をもう一度押すと解除する。重ねて選ぶことはしない（2 つとも選ぶのは絞らないのと同じ。メニューのときの ⌘クリックはやめた） |
| サイドバーの件数 | **範囲に合わせて数える**。画像に絞れば、フォルダ・タグ・スマートフォルダ・未分類などの件数がそれぞれの画像の数になる。0 件になった行も消さず、件数を薄くするだけ（行の位置を変えない。[UI.md](UI.md)） |
| 場所を移ったとき | 範囲は **残す**（今の「種類」と同じ）。アプリを開き直すと「絞らない」に戻る（今どおり。覚えない） |
| 「すべて解除」 | 範囲は **外さない**（今は種類も外している）。絞り込みの行にもう無いので、そこの「すべて解除」の対象にしない |
| 「条件を保存」 | 範囲も条件に入れて保存する（今どおり。「画像だけ」「動画だけ」のスマートフォルダが作れる） |
| スマートフォルダの条件に種類があるとき | 範囲と条件の両方に合うものを出す（今の `listKinds` と同じ）。合うものが無ければ、一覧に「条件に合うものはありません」を出す |
| 重複の候補 | 画像だけが対象なので、セグメントを **無効表示** にして「画像」を押した見た目にする。ツールチップに「重複の候補は画像だけが対象です」と書く。範囲の値そのものは変えない（ほかの場所へ移ると元の範囲に戻る） |
| 出すとき | 使っている種類が 2 つ以上のときだけ（今の「種類」のチップと同じ） |
| キー操作 | ⌥1・⌥2（画像・動画の順。使わない種類のキーは何もしない）で種類を 1 つ選び、⌥0 で解除する。同じ種類をもう一度押すと解除。メニューバーの「表示」→「種類で絞る」にも同じ項目を置く |

### 見た目

### 比べた案

| 案 | 形 | 選ばなかった理由・選んだ理由 |
|---|---|---|
| A リスト | 種類を件数付きで縦に並べる | 場所と重ねて選べることは分かりやすい。そのかわり 5〜6 行ぶんフォルダが下がる |
| B アイコン列 | アイコンを 1 行のセグメントに並べ、下に要約を 1 行 | 高さは小さいが、アイコンだけで種類を見分けられるかに頼る |
| **C メニュー** | 1 行のメニューボタン | **採用**（5 種類あったとき）。サイドバーの場所の並びをほぼ押し下げず、今の種類が文字で読める。切り替えは 2 クリックになるが、範囲は頻繁には変えないのでよい |
| **D セグメント** | ［画像｜動画］を 1 行に並べる | **2026-11-22 に採用**。種類が 2 つなら 1 行に入り、1 クリックで切り替えられ、今どちらかが見て分かる。高さはメニューと同じ |

## 実装で決めたこと

| 論点 | 決定 |
|---|---|
| 件数の数え方 | 件数を問い合わせ直さない。`get_counts` の `byKind`（固定の場所ごと）と、フォルダ・タグ・スマートフォルダの `byKind` が種類ごとの件数を持ち、画面は選んだ種類の分を足す（`inScope`、`lib/kinds.ts`）。範囲を変えてもサイドバーの件数はすぐ変わる |
| メニューの種類ごとの件数 | 今の場所の `byKind`（`placeByKind`、`store.ts`。サブフォルダ表示ならその合計）。ほかの絞り込みの条件は含めない |
| 「5 / 13 件」の分母 | 範囲に合わせる（サイドバーと同じ数。`placeTotal`） |
| 範囲だけを選んでいるとき | 絞り込みの条件には数えない（`activeConditions`）。タイトルは「5 / 13 件」にならず、絞り込みの行の「すべて解除」も無効のまま |
| 範囲に合うものが無いとき | 一覧に「ここに画像はありません」と「種類で絞らない」を出す |
| スマートフォルダを開いているとき | 条件に種類があれば、絞り込みの行の **末尾** に鍵付きの「種類」を出す（ほかの条件の位置は変えない）。条件を編集するときは、その種類を範囲に読み込み、保存・キャンセルで元の範囲に戻す |
| スマートフォルダを作ったとき | 範囲はそのまま（ほかの条件だけ外す） |
| 0 件の行 | 件数の数字を薄くする（場所の行はどれも同じ） |
| 画像サイズの絞り込み | **「サイズ（px）」にして動画にも効かせる**。縦横を持つのは画像と動画だけなので、いつでも使える（ほかの種類があったときは、混ざると無効表示にしていた。2026-11-22 にその処理を外した）。DB では今も縦横の条件は画像と動画だけに効く（`db.rs` の `PIXEL_KINDS`。フォントの古い行などは当たらない） |

コード：`Sidebar.tsx` の `KindRange`、`lib/kinds.ts` の `rangeKinds`・`inScope`、`lib/actions.ts` の `pickKind`、`commands.ts` の `kinds.*`、`db.rs` の `PlaceKinds`・`container_kinds`・`count_rule_by_kind`。

## 保留

- **場所の「すべて」の名前**：種類から「すべて」を外したので、今のところ変えない。それでも紛らわしければ「ライブラリ」などにする

## 一覧での見分け

**実装済み**。種類が混ざった一覧では、動画のコマ（決めたときは PDF の 1 枚目やブックマークのアイキャッチも）が画像と見分けにくい。モック（3 案）を比べて、A（左上の形式のチップ）にした。

| 論点 | 決定 |
|---|---|
| 置き場所 | サムネイルの **左上**。右上はお気に入り、右下は選択の印と再生時間、左下は紐づけが使っている。ピン留め・シェルフの印はチップの右に並ぶ（チップは先頭なので、印の有無で位置が動かない） |
| 中身 | アイコンと形式の大文字（`MP4`・`MOV`）。ツールチップに種類と形式の名前（「動画（MP4）」） |
| 色 | 動画は紫。写真の上に浮かぶ印なので、ダーク／ライトで色を変えない |
| 画像 | 出さない。サムネイルが中身そのもので、いちばん多い種類に印を付けると一覧がうるさくなる |
| 小さいサムネイル | 幅 120px 未満はアイコンだけにして、ピン留めとお気に入りの場所を残す |
| 重複の候補 | 出さない（画像だけが対象で、左上は「残す／ゴミ箱へ」が使う） |
| リスト表示 | 足さない。もともと形式の列がある |

比べた案：B 左上に色付きのアイコンだけ（控えめだが形式名はホバーしないと読めない）、C 名前の行の頭にアイコン（サムネイルを隠さないが、名前を出さない設定では効かない）。

コード：`lib/kinds.ts` の `kindChip`、`Grid.tsx` の `TopLeftMarks`。
