# 親子の紐づけ（計画）

1 つのファイルに別のファイルを紐づける。例：投稿予定の動画（親）に、サムネイル案の画像（子）をいくつか付けておく。
核になるのは親 1 つで、子はその付随物。**この文書は決定の記録で、実装はまだ。**

## 決めたこと

| 論点 | 決定 |
|---|---|
| 形 | 親子の 1 階層。`items.parent_id`（子が持つ）。子は 1 つの親だけに属し、子を親にはできない |
| 紐づけの前 | 普通のファイル。自分のフォルダ・タグ・評価・メモを持つ |
| 紐づけたとき | 子は親のフォルダへ移る（フォルダ 1 つの規則 = `item_folders` を守る）。この移動は `changes` に記録し、元に戻せる |
| 紐づいている間 | 子は親と常に同じ場所にいる。親のフォルダを変えると子も動く。子だけ別フォルダへ移す操作は無効表示（ツールチップに理由。`docs/UI.md`）。評価・メモ・タグは子が自分で持つ |
| 外したとき | 子は親のフォルダに残り、普通のファイルに戻る（元のフォルダには戻さない。戻すなら「元に戻す」） |
| 対象 | 親子とも同じモード（ストック）の項目。種類は問わない（画像・動画・テキスト・ファイル） |
| 一覧 | 親の行に「＋N」を出し、▸ で子を開く。フォントの「ファミリー 1 行・▸ で開く」（`openFamilies`・`rowIds`・`familyIds`）と同じ仕組みで作る。子を独立した行で出す切り替えは作らない |
| 検索・タグ・絞り込み・スマートフォルダ | 子だけが該当したときは、親の行を出して「中に該当あり」と示す |
| 親をゴミ箱へ | 設定で選べる（「子も一緒」「子は残す」）。既定は子も一緒。復元も一緒 |
| 採用の印 | 子のうち 1 つに付けられる（サムネイル案の採用）。2 回目の実装 |

## 有効・無効

ライブラリごとの設定（`library.db` の `settings`。「使う種類」と同じ置き場。docs/SETTINGS.md）。**既定は無効**。
無効のライブラリでは今までと何も変わらず、紐づけの操作はメニュー・コマンド・MCP とも無効表示にする（ツールチップ：設定で親子関係を有効にしてください）。

- **有効にする**：確認なし。紐づけなしで始まる
- **無効にする**：すべての紐づけ（`parent_id`）と採用の印を消す。データは引き継がない。
  確認ダイアログに件数を出す（例「親子の紐づけ 12 件を外します。子はいまのフォルダに残ります」）。外したあとは普通のファイルで、評価・メモ・タグはそのまま
- 無効にする操作は元に戻せない（確認ダイアログの件数表示だけで足りるとした。誤って切った場合は、有効にし直して紐づけ直す）
- 無効の間は紐づけが存在しないので、一覧・ゴミ箱・書き出し・共有・検索・MCP は今の動きのまま。「休止」の状態は持たない

## 実装の順序

1. 紐づける・外す、一覧のまとめと ▸ 展開、詳細パネルの「紐づけ」の節、検索の「中に該当あり」、設定の有効・無効
2. 親のゴミ箱の設定、書き出し（親子を 1 フォルダにまとめる）、フォルダ共有、ライブラリ間コピー（`transfer.rs`）、採用の印
3. 一覧へのドロップで紐づける、MCP のツール

操作は `src/lib/commands.ts` の表に足し、Rust のコマンドは `src/lib/api.ts` のラッパ経由で呼ぶ。モック `src/dev/mockBackend.ts` も同じ PR で更新する。
