# 親子の紐づけ

1 つのファイルに別のファイルを紐づける。例：投稿予定の動画（親）に、サムネイル案の画像（子）をいくつか付けておく。
核になるのは親 1 つで、子はその付随物。1 回目の実装（下の「実装の順序」の 1）まで済み。

## 決めたこと

| 論点 | 決定 |
|---|---|
| 形 | 親子の 1 階層。`items.parent_id`（子が持つ）。子は 1 つの親だけに属し、子を親にはできない |
| 紐づけの前 | 普通のファイル。自分のフォルダ・タグ・評価・メモを持つ |
| 紐づけたとき | 子は親のフォルダへ移る（フォルダ 1 つの規則 = `item_folders` を守る）。この移動は `changes` に記録し、元に戻せる |
| 紐づいている間 | 子は親と常に同じ場所にいる。親のフォルダを変えると子も動く。子だけ別フォルダへ移す操作は無効表示（ツールチップに理由。`docs/UI.md`）。評価・メモ・タグは子が自分で持つ |
| 外したとき | 子は親のフォルダに残り、普通のファイルに戻る（元のフォルダには戻さない。戻すなら「元に戻す」） |
| 対象 | 親子とも同じモード（ストック）の項目。種類は問わない（画像・動画・テキスト・ファイル） |
| 一覧 | 親の行に「＋N」を出し、▸ で子を開く。フォントの「ファミリー 1 行・▸ で開く」（`openFamilies`・`rowIds`・`familyIds`）と同じ仕組みで作る。子を独立した行で出す切り替えは作らない |
| 検索・タグ・絞り込み・スマートフォルダ | 子だけが該当したときは、親の行を出して「中に該当あり」と示す |
| 親をゴミ箱へ | 設定で選べる（「子も一緒」「子は残す」）。既定は子も一緒で、復元も一緒。「子は残す」は子の紐づけを外す（元に戻すと紐づけも戻る）。親と子を一緒に選んで入れたときは、どちらの設定でも一緒に入って紐づけは残る |
| 採用の印 | 子のうち 1 つに付けられる（サムネイル案の採用）。`items.adopted`（移行 26）、親ごとに 1 つ。外す・付け替える・別の親へ移すと消える。動画なら、採用した子を親の一覧サムネイルにできる（[VIDEO.md](VIDEO.md)「サムネイルを設定する」。印を付けただけでは変えない） |
| 親子の入れ替え | 子を「親にする」：その子が親になり、いまの親とほかの子（ゴミ箱の中の子も）はその下の子になる。みな同じフォルダにいるので、フォルダは変わらない。新しい親の採用の印は消え、ほかの子の印は残る。1 回の「元に戻す」で全体が戻る |
| 親だけを見る | 2 つの手段。① 表示メニューの「紐づけた項目をすべて開く／閉じる」（▸ を ⌥+クリックでも同じ）。② 絞り込みの行の「紐づけ」→「子を持つものだけ」（`Filter.parentsOnly`）。子を持つ = 同じ場所（どちらも一覧、どちらもゴミ箱）に子がいる。子も条件に合うものとして残し、親の行に畳む（▸ で開ける。ゴミ箱では畳まないので親だけ）。ほかの条件と重ねて子にだけ合うときは、今までどおり親の行に「中に該当あり」。スマートフォルダにも保存できる |

## 有効・無効

ライブラリごとの設定（`library.db` の `settings`。「使う種類」と同じ置き場。docs/SETTINGS.md）。**既定は無効**。
無効のライブラリでは今までと何も変わらず、紐づけの操作はメニュー・コマンド・MCP とも無効表示にする（ツールチップ：設定で親子関係を有効にしてください）。

- **有効にする**：確認なし。紐づけなしで始まる
- **無効にする**：すべての紐づけ（`parent_id`）と採用の印を消す。データは引き継がない。
  確認ダイアログに件数を出す（例「親子の紐づけ 12 件を外します。子はいまのフォルダに残ります」）。外したあとは普通のファイルで、評価・メモ・タグはそのまま
- 無効にする操作は元に戻せない（確認ダイアログの件数表示だけで足りるとした。誤って切った場合は、有効にし直して紐づけ直す）
- 無効の間は紐づけが存在しないので、一覧・ゴミ箱・書き出し・共有・検索・MCP は今の動きのまま。「休止」の状態は持たない

## 実装のメモ

- DB：`items.parent_id`（移行 25。`ON DELETE SET NULL`）。有効・無効は `settings` の `links`。`db.rs` の `link_items` / `unlink_items` / `restore_links`（元に戻す用の `Placement`）/ `set_links_enabled`
- フォルダ：`move_to_folder` と `remove_from_folder` は `with_linked` を通す。子だけを渡されたら動かさず、親が入っていれば子を連れて動く。MCP の `changes::move_to_folder` も同じ
- 一覧：`ItemQuery.withParents`（画面の一覧だけが付ける。書き出し・シェルフ・件数は付けない）で、該当した子の親を `Item.viaChild` 付きで足す。ゴミ箱・シェルフ・重複の候補では足さず、まとめもしない。まとめは `lib/grouping.ts` の `groupItems`（`Links`、`childIds` / `childMember`）、▸ の状態は `store.openParents`
- 画面：`LinkMark`（`Grid.tsx`）、`ParentPicker.tsx`、`LinksField.tsx`（詳細パネル）、設定の「親子の紐づけ」、絞り込みの行の `LinksCondition`（`FilterRow.tsx`）。操作は `commands.ts` の `item.link` / `item.unlink` / `item.makeParent` / `item.adopt`、`view.openParents` / `view.closeParents`（`store.setAllParents`）
- 入れ替え：`db.rs` の `make_parent`（元に戻す用に、関わった全員の `Placement` を返す）。MCP は `changes::make_parent`
- 別のライブラリへのコピー・移動（`transfer.rs`）：親を選ぶと子も一緒に運ぶ。相手のライブラリで親子の紐づけが有効なら、一緒に着いた親子だけを結び直す（採用の印も）。無効なら、ふつうの項目として着く。子だけを選んだときは、紐づけなしで着く（`parent_id` / `adopted` の列はそのままコピーしない）
- 重複の整理（`resolve_duplicates`）：ゴミ箱に入れる側が親なら、子は残す側へ引き継ぐ（残す側が子などで親になれないときは外す）
- 書き出し・フォルダの共有：子は親と同じフォルダにいるので、どちらも親子を特別に扱わず、ふつうの項目として同じフォルダに出る
- ドロップ：一覧の項目を別の項目へドラッグすると、その項目の子にする（`DragLayer.tsx` の `link:<id>`、行の `data-link`）。親になれる行（ストック・子でない）だけが的になり、手動並べ替えのフォルダでは行の中央だけが「紐づけ」、左右の端は今までどおり並べ替え
- 紐づけられるのはストックの項目だけ（フォントは今までどおりファミリーで見る）

## 実装の順序

1. **実装済み**：紐づける・外す、一覧のまとめと ▸ 展開、詳細パネルの「紐づけ」の節、検索の「中に該当あり」、設定の有効・無効、親のゴミ箱（子も一緒）
2. **実装済み**：親のゴミ箱の設定（`linksTrash`）、ライブラリ間コピー、重複の整理との整合、採用の印。書き出し・フォルダ共有は、親子が同じフォルダにいるので変更なし
3. **実装済み**：一覧へのドロップで紐づける（アプリの中のドラッグ。OS のファイルを項目へドロップして取り込みと同時に紐づけるのは、まだしない）、MCP のツール（`link_items` / `unlink_items` / `set_adopted`、`find_items` の「親」「採用」の列。変更は `changes.rs` に記録して元に戻せる）
4. **実装済み**：親子の入れ替え（「親にする」、MCP の `make_parent`）、紐づけた項目をすべて開く／閉じる、絞り込み「子を持つものだけ」、採用した子を動画のサムネイルにする

操作は `src/lib/commands.ts` の表に足し、Rust のコマンドは `src/lib/api.ts` のラッパ経由で呼ぶ。モック `src/dev/mockBackend.ts` も同じ PR で更新する。
