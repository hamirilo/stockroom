# 外部アプリで開く

取り込んだファイルを、外部アプリで見るときは原本を **読み取り専用** にして渡し、編集するときは **コピーを書き出して** 渡す。
入口は目的ごとに分け、開くたびにダイアログで聞くことはしない。

## なぜ考えたか

- 今の「既定のアプリで開く」（`commands.rs` の `open_items`）は、ライブラリの中の原本（`images/<id>/<元のファイル名>`）をそのまま渡している。
  外部アプリで上書きされると原本が変わり、ハッシュ・サムネイル・重複の判定とずれる。「元のファイルは書き換えない」（[ROADMAP.md](ROADMAP.md)）が、アプリの外からは守れていない
- アプリが「別名で保存」を元のファイルと同じフォルダに提案すると、ライブラリの中に Stockroom の知らないファイルができる
- PDF のページを展開して見る機能を Stockroom に入れるかを考えたのがきっかけ。下の「範囲」のとおり、見る・編集するは外部アプリに任せる

## 範囲

| | 決定 |
|---|---|
| Stockroom がすること | 集める・探す・取り出す（取り込み・整理・サムネイル・ビューアでの表示、今のまま） |
| 外部アプリに任せること | 開いて読む・編集する（PDF のページを展開して見る・ページの整理・書き込みなど） |
| 特定のアプリ向けの処理 | 作らない（PDF の専用アプリなどを前提にしない）。入口は「外部アプリで開く」だけを用意する |
| ファイルの管理 | Stockroom に残す。PDF の専用アプリにはフォルダ・タグなどの管理を入れない（[FONT_APP.md](FONT_APP.md) と同じ線引き：使う場面でアプリを分ける） |

## 決めたこと

| 論点 | 決定 |
|---|---|
| 入口 | 目的ごとに分ける。**見る**：「既定のアプリで開く」「アプリを選んで開く…」。**編集する**：「編集用に書き出して開く」 |
| 開くときの確認 | 出さない。開くのは取り消せない操作でも判断が要ることでもない（[NOTIFICATIONS.md](NOTIFICATIONS.md)）。毎回出すと読まずに押されて、警告の意味がなくなる。今ある「11 件以上を開くときの確認」はそのまま |
| 見るときに渡すもの | 原本。渡す前に読み取り専用にする。上書きしようとすると、外部アプリ自身が「読み取り専用」「別名で保存」と案内する |
| 読み取り専用にする時 | **外部アプリで開くときだけ**。取り込んだときには付けない（今のライブラリを移行しなくて済む）。開いたものから順に守られる。一度付けたら外さない。Finder などから直接開いた場合は守れない |
| アプリを選んで開く | 足す。macOS はアプリを選ぶ画面、Windows は「プログラムから開く」。渡すものは既定のアプリと同じ（読み取り専用の原本） |
| 編集するときに渡すもの | コピー。表示名をファイル名にして書き出し、それを既定のアプリで開く。コピーには Stockroom が付けた読み取り専用を残さない |
| コピーの置き場所 | 既定は **書類/Stockroom**（macOS は `~/Documents/Stockroom`、Windows はドキュメントの中の `Stockroom`）。初めて書き出すときに作る。設定で変えられる。同じ名前があれば連番を付ける（書き出しと同じ） |
| コピーのその後 | 書き出した時点で利用者のファイル。Stockroom は覚えず、消さない。編集したものを取り込み直すときは、ウィンドウへドロップする |
| 対象の種類 | ブックマーク以外のすべて（画像・ファイル・テキスト・動画）。ブックマークは今のままブラウザで開く |
| 回転・反転した画像 | 書き出しと同じく、元の向きのまま渡す（[FEATURES.md](FEATURES.md)） |

## 防げないこと

読み取り専用で防げるのは、ファイルをそのまま上書きする保存だけ。

| 保存のしかた | macOS | Windows |
|---|---|---|
| ファイルをそのまま上書き（Word・Excel など） | 防げる | 防げる |
| 同じフォルダに一時ファイルを作って差し替える | **防げない**（フォルダに書き込めれば差し替えられる） | 防げる |
| 同じフォルダに新しいファイルを作る（別名で保存） | **防げない** | **防げない**（フォルダの読み取り専用の属性は効かない。防ぐにはアクセス権（ACL）の設定が要る） |

フォルダを読み取り専用にしたりアクセス権を変えたりはしない。Stockroom 自身の書き込みやバックアップ・同期への影響が大きいため。
気づく仕組み（下の「後回しにしたこと」）で補う。

## 後回しにしたこと

- **後から気づく仕組み**：ウィンドウに戻ってきたときに、外部アプリで開いた項目を確かめる。原本が変わっていたら「新しい版として取り込む」、
  項目のフォルダに知らないファイルがあれば「取り込む」をトーストで知らせる。実際に困ってから足す
- 編集したコピーが変わったら取り込みを提案する（コピーを覚えておく必要があるので、今回はしない）

## 実装のメモ

- `src-tauri/src/open_external.rs`：`open_items`（既定のアプリ）、`open_items_with`（アプリを選んで）、`open_for_edit`（編集用に書き出して）、
  `default_edit_folder`（設定画面に出す既定の書き出し先）。画面からは `src/lib/actions.ts` の `openSelection` / `openSelectionWith` / `openSelectionForEdit`
- 入口はコマンド表 `src/lib/commands.ts` の `item.open` / `item.openWith` / `item.openForEdit`。メニューバーの「ファイル」と一覧の右クリックで「既定のアプリで開く」の下に並べる（[MENUS.md](MENUS.md)）。
  ブックマークだけを選んでいるときは、下の 2 つは無効表示。詳細パネルの下のボタンは増やさない（位置を変えない、[UI.md](UI.md)）
- 11 件以上を開くときは、3 つとも同じ確認を出す（それぞれがウィンドウを開くため）
- 読み取り専用：`library.rs` の `protect` / `unprotect`。macOS は書き込みの権限を外す（戻すときは持ち主だけ書ける）、Windows は読み取り専用の属性。ファイルだけで、フォルダには付けない。
  付けられなくても（属性の無いファイルシステム）開くのは止めず、ログに残す
- **Stockroom 自身の書き込みの前に外す**：テキストの保存（`texts/commands.rs`。Windows は読み取り専用のファイルへ差し替えられない）、項目のフォルダを消すとき（`library::remove_item_dir`。ゴミ箱を空にする・完全に削除・取り込みに失敗したときの片付け）
- **コピーに属性が移る**：Rust の `fs::copy` は権限・属性も写すので、写した先で外す。書き出し・ライブラリ全体の書き出し（`export::copy_out`）、編集用の書き出し（同じ関数）、別のライブラリへのコピー（`transfer.rs` の `copy_dir`）
- アプリを選ぶ画面：macOS は「このアプリで開く」の選択画面を出す公開の API が無いので、アプリケーションのフォルダを開いたファイル選択（`.app`）で選ばせ、`open -a` で渡す。
  Windows は `SHOpenWithDialog`（「常にこのアプリを使う」は出さない。既定のアプリを変えない）。ファイルごとに出し、キャンセルしたら残りは開かない
- 書き出し先の設定：`settings.json` の `editFolder`（無ければ書類/Stockroom、初めて書き出すときに作る）。設定画面の「一般」の「外部アプリで編集」で変更・既定に戻す
- 書き出したあとは、件数と書き出し先をトーストで知らせる（「書き出し先を表示」付き）
