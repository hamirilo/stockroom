# ロードマップ

Eagle（jp.eagle.cool）との比較をもとにした、AI 以外の機能追加の計画。
方針は変えない：**取り込んだ元ファイルは書き換えない**（テキストだけはアプリで編集できる例外。docs/TEXT.md）、ライブラリは 1 フォルダで完結、軽量。

規模の目安：S = 1〜2 日、M = 3〜5 日、L = 1〜2 週間以上。

## 一覧（優先順）

対応済みのもの：

- **シェルフ（旧・作業台）・まとめて出力**：一覧の下に一時的に集める「シェルフ」（`tray` テーブル。フォントは比較にも使う。docs/FONT_UI.md）と、選んだ画像を番号付きで 1 枚の PNG / JPEG か 1 つの HTML にまとめる「まとめて出力」（`src/lib/sheet.ts`、`src-tauri/src/sheet.rs`）。レイアウトと描画はフロントエンド（プレビューと出力で同じ計算を使う）、Rust は各画像を向きを反映して必要な大きさに縮小して渡すだけ。フェーズ 3 の一括エクスポートも、対象を作業台から選べるようにする

- **SVG**：取り込み・一覧・ビューアで使える。サムネイルと類似判定用には resvg で長辺 1024px にラスタライズし、ビューアではブラウザが SVG をそのまま描画する（`src-tauri/src/formats.rs`）。
- **色分け**：フォルダ・スマートフォルダ・タグに 9 色。今のままで十分なので追加はしない。

## フェーズ 1：回転・反転（S〜M）

**決定**：向きの情報だけを保存する（非破壊）。元ファイルは書き換えない。

- 操作：90° 右回転・左回転、左右反転、上下反転、元の向きに戻す
  - 一覧・ビューアの右クリックメニュー、ショートカット（例：⌘⇧R 右回転 / ⌘⇧L 左回転）
  - 複数選択でまとめて適用。元に戻せる
- データ：`items.orientation`（EXIF の向きと同じ 1〜8 の表現）を追加。回転・反転はこの値の合成で表す
- 表示
  - サムネイルを向きを反映して作り直す
  - ビューアは CSS の `transform` で回す
  - 幅・高さ（縦長／横長の絞り込み、並び替え、レイアウト計算）は向きを反映した値を使う
- 書き出し：フェーズ 3 の書き出しで向きを反映した画像を作る。それまでは元ファイルをそのまま書き出す
- 対象外：SVG は回転できるが、類似判定用のハッシュは元の向きのまま（判定に影響しない）

## フェーズ 2：フォント（M）

**決定**：TTF / OTF / WOFF / WOFF2 / TTC / OTC に対応する。

- 先に `items.kind`（`image` / `font`、後で `video`）を追加し、形式ごとに処理を分ける
  - 完全一致の重複判定（SHA-256）はそのまま使える
  - 類似判定（重複の候補）は画像だけを対象にする
  - 幅・高さはフォントでは 0。縦長／横長・画像サイズの絞り込みでは対象外になる
- サムネイル：フォント名とサンプル文字（"Aa あア 永"）を Rust で描画して PNG を作る
  - WOFF / WOFF2 は展開してから描画する（WOFF2 の展開には allsorts など純 Rust のライブラリを使う予定。実装時に確認）
- TTC / OTC：**1 ファイル = 1 件** として扱う。サムネイルは最初のフォント、ビューアと詳細パネルで中のフォントを切り替えて見られる
- ビューア：`@font-face` で読み込み、任意の文字を入力・大きさを変えて確認。文字の一覧表示
- 詳細パネル：ファミリー名・スタイル・グリフ数・（TTC なら）含まれるフォントの一覧。可変フォントの軸、製作者、版も表示
- 絞り込み：種類（画像／フォント）で絞れるようにする → サイドバーの「種類」（`Filter.kinds`。動画を足すときは `KINDS` に追加）
- 持ち出し：⌘C・ドラッグ・書き出しは元ファイルのまま

## フェーズ 3：一括エクスポート（M）

**用途**：HEIC などを JPEG に変換、一定のサイズで出力、Web 用に JPEG で縮小、PNG などへの形式変換。

今の書き出しを、オプション付きのダイアログに置き換える。

- 対象：選択中の画像／表示中の一覧すべて（フォルダ・スマートフォルダ・絞り込み結果）
- 形式：元のまま／JPEG／PNG／WebP。JPEG・WebP は品質（例：85）
  - 透過画像を JPEG にするときの背景色（白）
  - HEIC・AVIF・TIFF・SVG も変換できる（デコードは今の `formats::decode` を使い回す）
- サイズ：元のまま／長辺 N px に縮小（拡大はしない）
- 向き：フェーズ 1 の回転・反転を反映する
- プリセット：よく使う設定を保存する（初期値として「Web 用：JPEG・品質 85・長辺 2000px」）
- 同名ファイル：連番を付ける（今と同じ）
- 進捗表示とキャンセル。rayon で並列処理（取り込みと同じ）
- フォントは変換の対象外（元ファイルのままコピー）

形式の変換は「書き出し時に変換する」に寄せる。ライブラリ内のファイルを別形式に置き換える機能は作らない。

予定に入れていないもの（必要になったら追加）：タグ・評価・メモの CSV/JSON 書き出し。フォルダ構成の再現は、ライブラリ全体の書き出しとして [EXPORT.md](EXPORT.md) で予定に入れた。

## フェーズ 4：ファイル名の一括変更（S）

- 選択中の画像に対して「名前を一括変更…」ダイアログ（複数選択時の F2）
- 方式：テンプレート（`{name}` `{n}` 連番 `{date}` `{w}x{h}` `{ext}` `{folder}`）／置換（正規表現の有無）／前後に追加
- 変更前 → 変更後のプレビュー、重複する名前の警告、元に戻す
- 名前は DB 上の表示名だけで、ディスク上のファイルは変えない（安全）。書き出し時のファイル名はこの表示名を使う
- フェーズ 3 の書き出しでもファイル名テンプレートを使えるようにする

## フェーズ 5：スマートフォルダのルール編集 UI（M）

今は「一覧上部の検索・絞り込みの状態 = ルール」で、保存した条件が見えにくく、「すべて／いずれか」の切り替えはタグにしか無い。

- 専用のダイアログ
  - 「次の **すべて／いずれか** に一致」
  - 条件の行：`[項目] [演算子] [値]`、行の追加・削除
  - 項目：名前／メモ／タグ／フォルダ／評価／お気に入り／ピン留め／種類／形式／縦横／幅／高さ／ファイルサイズ／追加日
  - 演算子：含む・含まない・等しい・以上・以下・範囲・〜日以内 など
  - 「一致：N 件」をリアルタイム表示
- データ：`Rule` を `{ match: "all" | "any", conditions: [...] }` に広げ、既存のルールは読み込み時に変換
- 今の「一覧上部の条件から作る」（⌘⇧⌥N）は残す

## フェーズ 6：Chrome 拡張からの取り込み（L）

**実装済み**（`src-tauri/src/webimport.rs`、`extension/`）。計画からの変更点：

- 画像は拡張機能がダウンロードしてバイト列を送る（アプリは URL を取りに行かない）。ログインが必要なサイトの画像もブラウザの Cookie で取れ、会社のプロキシ設定もブラウザのものがそのまま使われる。拡張からの取得が拒否されたら、ページ自身に取得させる
- 接続キーは手で扱わない。アプリが「フォルダを用意」で書き出す拡張機能には `config.json` に入れて渡し、それ以外の場所から入れた拡張機能は「アプリと接続」で求め、アプリでユーザーが許可する（両方に同じ 4 桁の番号を表示）
- 受付はオフが初期値（「ブラウザ拡張と連携」でオンにする）。ポートは 41620 固定
- 保存した画像の `items.source_url` は元のページの URL。すでにある画像を別のページから保存しても最初のページのまま（タグは追加される）
- 中身から形式を判定して拡張子を直す（URL に拡張子がない画像、拡張子と中身が違う画像）
- 取り込みは同時に 1 つずつ（拡張機能とドロップが重なっても重複判定が漏れないように）

- アプリ側：起動中だけ `127.0.0.1` で HTTP サーバーを開く（Eagle と同じ方式）
  - `POST /import`（画像の URL またはデータ、元ページの URL・タイトル、保存先フォルダ、タグ）、`GET /folders`
  - 127.0.0.1 のみで待ち受け、アプリが生成したトークンを要求、拡張以外の Origin は拒否
  - `items.source_url` を追加し、詳細パネルに表示
- 拡張側（Manifest V3、`extension/`）
  1. 画像の右クリック保存、Alt+右クリックで即保存
  2. ポップアップで保存先フォルダ・タグを選ぶ
  3. ページ内の画像を一覧して一括保存（サイズ・形式で絞り込み）
  4. 表示中のタブのスクリーンショット
- 配布：最初は「パッケージ化されていない拡張機能を読み込む」。ウェブストア公開は後で判断

## フェーズ 7：動画（L）— 実装済み（[VIDEO.md](VIDEO.md)）

- 対象：MP4 / WebM / MOV（WebView で再生できるもの）
- サムネイルは OS の機能で 1 フレームを切り出す（macOS は AVFoundation、Windows はシェルのサムネイル API）。ffmpeg の同梱はインストーラが数十 MB 増えるので避ける
- 一覧は静止サムネイル＋再生時間。ホバーでのコマ送りプレビューは後回し
- ビューアは `<video>` で再生。詳細パネルに再生時間・解像度・コーデック

## フェーズ 8：ファイル（PDF・オフィス文書）（M）

**決定**（2026-10-09）：3 つ目のモード「ファイル」（`items.kind = 'file'`）として、PDF とオフィス文書を受け付ける。
専用の機能は作らず、取り込み・整理（タグ・フォルダ・評価・メモ）とサムネイルまで。編集・再生は OS の既定のアプリに任せる。

- 対象：PDF / doc・docx / xls・xlsx / ppt・pptx / pages / numbers / key。「何でも受け付ける」にはしない
  - 動画・音声は当面対象外。入れるときもこのモードに「ファイルとして」足すだけで済む（専用の機能が要るなら `video` に分ける）
- サムネイル（`src-tauri/src/files/`）：上から順に、作れたものを使う
  1. OS：macOS は `qlmanage -t`（Quick Look。PDF・Office・iWork）、Windows は PDF だけ Windows.Data.Pdf
  2. ファイルの中のプレビュー：iWork の `preview.jpg`、Office の `docProps/thumbnail.jpeg`（サムネイル付きで保存したとき。PowerPoint は既定で付く）
  3. 種類のカード（「PDF」「XLSX」などを色付きで描いたもの）
  - Quick Look は壊れたファイルで真っ白な画像を返したり（→ 失敗扱い）、止まったりする（→ 20 秒で打ち切り）
  - Windows のシェルのサムネイル API は Office ではファイル内のプレビューを読むだけなので使わない
- 幅・高さは 0（フォントと同じ）。レイアウトはグリッド／リスト。回転・似た画像の検出・画像サイズの絞り込みは対象外
- ビューア：PDF は WebView の PDF 表示（`<iframe>`）、オフィス文書はサムネイルと「既定のアプリで開く」
  → 2026-10-09 に全ページのプレビューを追加（`files/preview.rs`）。初めて開いたときに作り、`previews/` に残す
  - macOS：Quick Look のプレビュー（`qlmanage -p -o`）。Word は全文、Excel はシートのタブ付きの HTML。
    `previews/<id>.qlpreview/` をビューアの `<iframe sandbox="allow-scripts">` で表示
  - Windows：Office が入っていれば、Office に PDF へ書き出させる（`files/win_office.rs`、PowerShell から COM）。
    `previews/<id>.pdf`。読み取り専用・マクロ無効・パスワード付きは失敗扱い、90 秒で打ち切って自動化で起動した Office を終了
  - Windows のサムネイル：ライブラリを開いたときと取り込みの後に、裏で 1 件ずつ PDF を作り、1 ページ目をサムネイルにする
    （`files/thumbs.rs`、`<id>_p.*`）。Office が無ければ何もしない
  - どちらで作ったものも両方の OS で表示する（PDF を優先）
- パッケージ形式（フォルダ）の古い iWork 文書は取り込まず、中身も取り込まない

今後の候補：PDF のページ数、PDF の中の文字での検索。

## フェーズ 9：フォルダの共有（M）

**決定**（2026-10-14）：自分のスマホや同僚数人に、特定のフォルダを見るだけで共有する。アプリの中で小さな HTTP サーバーを
LAN に開く（`src-tauri/src/share.rs`）。静的な HTML の書き出し（まとめて出力の延長）より、アプリで変えたものがすぐ見える方を選んだ。
Web から編集できる版（今の UI を HTTP 越しに動かす）は作らない。

- 単位はフォルダ。サブフォルダの中も見せ、共有したフォルダより上やその隣へは行けない（どの要求も、共有したフォルダの中にあるかを確かめる）
- 見せるもの：名前・種類・大きさ・サムネイル・画像（回転・反転を反映）、元のファイルのダウンロード（フォルダごとにオフにできる）。
  見せないもの：メモ・タグ・評価・保存元のページ。ゴミ箱の中のもの
- 共有は `library.db` の `shares` テーブル（フォルダ・URL の秘密の文字列・ダウンロードの可否）。フォルダを消すと共有も消える。
  アプリを再起動しても続き、同僚がブックマークした URL がそのまま使える
- サーバーは、開いているライブラリに共有中のフォルダがあるときだけ `0.0.0.0:41640` で待ち受ける（ほかの 2 つのサーバーと違い、LAN から届く）。
  URL の文字列（122 ビットの乱数）が唯一の鍵。HTTP なので暗号化はしない。GET だけ
- 閲覧ページは React の UI を使い回さず、スマホ向けの 1 ファイル（`src-tauri/src/share.html`）をアプリに埋め込む。外部のスクリプトは読まない（CSP）
  - 一覧（サブフォルダ・サムネイル）、タップでビューア（スワイプで前後、戻るで閉じる）、ダウンロード
  - ページを開き直したとき・アプリに戻ってきたときに読み直す
- URL のアドレスは、このパソコンが外へ出る経路のアドレスを先頭に、ほかのアドレス（VPN など）も選べる。macOS は `.local` の名前も出す
- 共有ダイアログ：URL・QR コード（`qrcode` クレートで SVG）・コピー・ブラウザで開く・ダウンロードの可否・注意書き・つながらないときの手順。
  設定の「フォルダの共有」に一覧

今後の候補：有効期限・パスワード、スマートフォルダや作業台の共有、まとめて ZIP でダウンロード、アクセスの記録（いつ・どの端末から見られたか）、
フォントの見本・PDF のプレビューを共有ページでも見せる。

## まだ予定に入れていない Eagle の機能（参考）

- カラー検索（画像の主要な色で探す）
- 画像上の注釈（位置付きのメモ）
- アクション（条件に合う画像へ自動でタグ付け・フォルダ移動）
- フォルダのタグを、そのフォルダへ入れた画像へ自動で付ける
- 音声・Web ブックマーク・YouTube などのブックマーク
- プラグインの仕組み
