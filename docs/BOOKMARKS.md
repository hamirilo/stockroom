# URL（ブックマーク）

Web ページの URL を、画像・ファイルと同じフォルダ・タグで保管する。**設計メモ（未実装）。** 決めたことと、まだ決めていないことを分けて書く。

## 決めたこと

- **用途**：ブックマーク（リンクを並べて保管）と、ページの中身の保存
- **集める手段**：拡張機能・アプリへの貼り付け・外部アプリ（Feedability の「リンクだけ送る」、docs/FROM_APPS.md）
- **通信の原則：外へ取りに行くのは拡張機能だけ。アプリは URL を取りに行かない**（今の方針のまま。docs/ROADMAP.md の「アプリは URL を取りに行かない」）
  - タイトル・ファビコン・アイキャッチ（`og:image`）・説明文は、拡張機能がページから読んで送る。
    ログインが必要なサイトも、会社のプロキシも、ブラウザのものがそのまま使われる
  - 貼り付けと外部アプリからの登録は、取得なしで登録する。タイトルは受け取った値か URL のホスト名、画像は無し
  - したがって CSP・capabilities・待ち受けポートは変えない（CLAUDE.md「変えないもの」）
- **管理で重視すること**：タイトル・ファビコンの自動取得（上のとおり拡張機能から）、リンク切れの確認・重複チェック、検索・絞り込み
- モードにはしない。画像・ファイルと同じ「ストック」の中の種類にする（docs/ARCHITECTURE.md「今後」）

## まだ決めていないこと

- **リンク切れの確認**：アプリは通信しないので、今の原則ではできない。拡張機能から確認する（ページを開いたときに記録する等）か、手動の操作として通信を許すか
- **重複チェック**：URL の正規化（末尾のスラッシュ、`utm_*` などの追跡パラメータ、フラグメント）をどこまでやるか。重複したときは追加せず既存を示すのか、タグだけ足すのか（画像の保存と同じ扱いにするのが自然）
- **データの形**：`Item` はファイル前提（`fileName`・`ext`・`size`）。URL の項目に何を持たせるか（URL・タイトル・説明文・ファビコン・アイキャッチ）。画像は外から読まない方針なので、ファビコンとアイキャッチは DB に保存してサムネイルとして使う
- **ページの中身の保存**：本文を Markdown（`.md`）のテキスト項目として別に作るのが既存の仕組みに乗る。ブックマークとの関係（リンクで結ぶか、同じ項目か）
- **受け口**：`POST /import` にタイトル・説明文・ファビコン・アイキャッチを足すか、`POST /bookmark` を別に作るか
- **画面**：一覧での見せ方、詳細パネル、貼り付けの入口の位置。docs/UI.md の原則に沿って決める
- **検索・絞り込み**：URL・ドメイン・タイトルで探す。MCP の `find_items` の出力と条件にも足す
