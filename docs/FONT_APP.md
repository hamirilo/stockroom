# フォントを別のアプリにする

**方針を決めた段階**。決めたことは「決めたこと」、まだ決めていないことは「詰めること」に書く。

## なぜ分けるか

[MODES.md](MODES.md) でフォントをモードとして完全に分けた結果、ストックとフォントがアプリの中で共有しているものはほとんど無くなった。

| | 今の状態 |
|---|---|
| 一覧に出るもの | ストックにフォントは出さない。フォントモードにはフォントだけ |
| フォルダ・タグ・スマートフォルダ | モードごとに別々（`mode` 列） |
| お気に入り・ピン留め・ゴミ箱・シェルフ | モードの中だけで数える。シェルフの役目も違う（ストックは書き出し・まとめて出力、フォントは比較） |
| 画面 | 一覧・見本・比較・この端末のフォント（[FONT_UI.md](FONT_UI.md)、[SYSTEM_FONTS.md](SYSTEM_FONTS.md)）はフォントだけのもの |
| 共有しているもの | ライブラリのファイル（`library.db`）と、アプリの外側（ウィンドウ、設定、取り込み・書き出し・ライブラリ間のコピー、更新） |

中身はもう別々で、入れ物だけが同じという状態になっている。使う場面も違う（画像・ファイルは「探して使う」、フォントは「比べて選ぶ」。[ARCHITECTURE.md](ARCHITECTURE.md)）。
この端末のフォントの一覧も、もともと別のアプリ（font-preview）で見ていたものを取り込んだ機能だった。

1 つのアプリにまとめておくことで払っているもの：

- ストックの画面にモードの切り替えがあり、モードごとにレイアウト・グループ分け・シェルフの操作が変わる（`MODE_LAYOUTS` / `MODE_GROUPS`、`listKinds`、`modeOf`）。[UI.md](UI.md) の「切り替えで操作の位置を不必要に変えない」を守るための手間がここにかかる
- DB にもモードの区別がある（`folders` / `tags` / `smart_folders` の `mode` 列、`mode_where`、移行の `split_modes`）
- フォントの機能を足すとき、ストックの画面・メニュー・コマンドとぶつからないかを毎回確かめる

## 前に見送ったときの懸念

以前は「分けるとエコシステムが二重になる」として見送り、[ARCHITECTURE.md](ARCHITECTURE.md) に「別アプリに切り出す案は保留中」とだけ残していた。
二重になるのは、コード（ウィンドウ・設定・更新などアプリの土台）と配布（ビルド、署名、アプリ内アップデート、リリース）だった。

今回は、土台の二重化は **アプリの土台を共通の部品（core）にして、ほかのアプリと一緒に共有する** ことで解く。
土台が二重なのはフォントのアプリと Stockroom の間だけの話ではなく、pdf-one・desktop-apps・Feedability にも同じものがある。

## 方針

1. **フォントは Stockroom の中のモードではなく、別のアプリにする。** Stockroom はストック（画像・ファイル・テキスト・動画・ブックマーク）、フォントのアプリはフォントだけを扱う
2. **フォントのアプリは別のリポジトリ・別の名前にする。** このリポジトリをコピーして始め、そこから先は別のアプリとして育てる。版の番号も別々に上げる
3. **互換性は考えない。** フォントのアプリはフォント専用で、Stockroom のライブラリは開かない。今のフォントは、ファイルを書き出して新しいアプリに取り込み直す（タグ・フォルダ・評価は引き継がない）
4. **アプリの土台は共通の部品（core）にする。** 置き場所は desktop-platform。範囲はアプリの土台だけ（ウィンドウ・メニュー・設定・トースト・更新・ログ・コマンド表など、どのデスクトップアプリでも使うもの）。ライブラリや取り込み、フォルダ・タグなど「集めて整理する」仕組みは入れない
5. **順番はフォントのアプリが先、core が後。** 先にフォントのアプリを作って動かし、2 つに本当に共通している部分を見てから core に切り出す
6. **フォントのアプリが使えるようになったら、Stockroom からフォントのコードを消す**

## 決めたこと

| 論点 | 決定 |
|---|---|
| リポジトリと名前 | フォントのアプリは別のリポジトリ・別の名前。名前はまだ決めない（この文書では「フォントのアプリ」） |
| 版の番号 | Stockroom とは別々に上げる |
| ライブラリ | フォントのアプリはフォント専用。Stockroom のライブラリとの互換性は考えない |
| 今のフォント | 新しいアプリに取り込み直す。タグ・フォルダ・評価は引き継がない |
| アプリ内アップデート | 署名の鍵は Stockroom と共通。配信先はフォントのアプリのリポジトリのリリース（リポジトリが別なので「最新」を取り合わない） |
| ブラウザ拡張・Claude（MCP） | フォントのアプリには入れない。待ち受けのポートは Stockroom の 1 つのまま |
| フォルダの共有 | フォントのアプリには入れない（最初のコピーで外す） |
| Stockroom のフォントのコード | フォントのアプリが使えるようになったら消す。モードの仕組みも一緒に片付ける |
| core | desktop-platform に置く。アプリの土台だけ。使うのは Stockroom・フォントのアプリ・pdf-one・desktop-apps・Feedability |
| 順番 | フォントのアプリが先、core が後 |

## 詰めること

### 名前と ID（人が決める）

[CLAUDE.md](../CLAUDE.md) の「変えないもの」に当たるので、人が決める。

- 名前（リポジトリ名・製品名 `productName`）と `identifier`
- アイコン

### フォントのアプリ

- 書き出し・ライブラリ間のコピーを残すか（最初のコピーでは残し、要らなければ後で外す）
- コピーしたあと、ストックの種類（画像・ファイル・テキスト・動画・ブックマーク）とモードの仕組みをどこまで消すか。消すほどコピーは軽くなるが、作業が増える
- この端末のフォント（[SYSTEM_FONTS.md](SYSTEM_FONTS.md)）は、フォントのアプリでも今の形のままでよいか
- 対応する OS（macOS・Windows の両方か）
- 機能ごとの文書（[FONT_UI.md](FONT_UI.md)・[SYSTEM_FONTS.md](SYSTEM_FONTS.md) など）は、フォントのアプリのリポジトリへ移す

### Stockroom からフォントを消すとき

- 消すもの：`features/fonts/`・`src-tauri/src/fonts/`・モードの切り替え・モードごとのレイアウト／グループ分け／シェルフの操作
- DB の `mode` 列など、もう使わないものの扱い（残して無視するか、移行で消すか）
- フォントの入ったライブラリを開いたとき（フォントは一覧に出なくなる。消すか、残して見せないか）
- [MODES.md](MODES.md)・[ARCHITECTURE.md](ARCHITECTURE.md) などの文書の直し

### core

- 何を入れるか：Stockroom・フォントのアプリ・pdf-one・desktop-apps・Feedability に共通しているものを見比べて決める
- 形：フロントエンド（npm のパッケージ）と Rust（クレート）をどう配るか。desktop-platform からの参照の仕方（git の依存、ワークスペースなど）
- 版の合わせ方：core を直したとき、各アプリにどう取り込むか

### 社内版

社内版（jazmf-dx/stockroom の `docs/CORP.md`）はもともとフォントを外しているので、影響は小さい見込み。core に切り出したあと、社内版のビルドがそのまま通るかは確かめる。

## 進め方（案）

1. 名前を決め、フォントのアプリのリポジトリを作る（人の作業）
2. このリポジトリをコピーし、フォントに要らないもの（ブラウザ拡張・Claude・フォルダの共有など）を外す
3. 今のフォントを取り込み直し、自分で使って確かめる。この間、Stockroom のフォントのモードは残しておく
4. Stockroom からフォントのコードとモードの仕組みを消す
5. Stockroom・フォントのアプリ・ほかのアプリを見比べ、アプリの土台を core として desktop-platform に切り出す
