# フォントを別のアプリにする

**Stockroom からフォントを消した**（進め方の 4 まで）。決めたことは「決めたこと」、まだ決めていないことは「詰めること」に書く。
以下の「今の状態」「1 つのアプリにまとめておくことで払っているもの」は、消す前の Stockroom のこと。

## なぜ分けるか

`MODES.md`（今は hamirilo/typecase）でフォントをモードとして完全に分けた結果、ストックとフォントがアプリの中で共有しているものはほとんど無くなった。

| | 今の状態 |
|---|---|
| 一覧に出るもの | ストックにフォントは出さない。フォントモードにはフォントだけ |
| フォルダ・タグ・スマートフォルダ | モードごとに別々（`mode` 列） |
| お気に入り・ピン留め・ゴミ箱・シェルフ | モードの中だけで数える。シェルフの役目も違う（ストックは書き出し・まとめて出力、フォントは比較） |
| 画面 | 一覧・見本・比較・この端末のフォント（`FONT_UI.md`、`SYSTEM_FONTS.md`。今は hamirilo/typecase）はフォントだけのもの |
| 共有しているもの | ライブラリのファイル（`library.db`）と、アプリの外側（ウィンドウ、設定、取り込み・書き出し・ライブラリ間のコピー、更新） |

中身はもう別々で、入れ物だけが同じという状態になっている。使う場面も違う（画像・ファイルは「探して使う」、フォントは「比べて選ぶ」。[ARCHITECTURE.md](ARCHITECTURE.md)）。
この端末のフォントの一覧も、もともと別のアプリ（font-preview）で見ていたものを取り込んだ機能だった。

1 つのアプリにまとめておくことで払っているもの：

- ストックの画面にモードの切り替えがあり、モードごとにレイアウト・グループ分け・シェルフの操作が変わる（`MODE_LAYOUTS` / `MODE_GROUPS`、`listKinds`、`modeOf`）。[UI.md](UI.md) の「切り替えで操作の位置を不必要に変えない」を守るための手間がここにかかる
- DB にもモードの区別がある（`folders` / `tags` / `smart_folders` の `mode` 列、`mode_where`、移行の `split_modes`）
- フォントの機能を足すとき、ストックの画面・メニュー・コマンドとぶつからないかを毎回確かめる

## 前に見送ったときの懸念

以前は「分けるとエコシステムが二重になる」として見送り、[ARCHITECTURE.md](ARCHITECTURE.md) に「別アプリに切り出す案は保留中」とだけ残していた。
二重になるのは、コード（ウィンドウ・設定・更新などアプリの土台）と配布（ビルド、署名、アプリ内アップデート、リリース）だった。

今回は、土台の二重化は **アプリの土台を共通の部品（core）にして、ほかのアプリと一緒に共有する** ことで解く。
土台が二重なのはフォントのアプリと Stockroom の間だけの話ではなく、pdf-one・desktop-apps・Feedability にも同じものがある。

## 方針

1. **フォントは Stockroom の中のモードではなく、別のアプリにする。** Stockroom はストック（画像・ファイル・テキスト・動画・ブックマーク）、フォントのアプリはフォントだけを扱う
2. **フォントのアプリは別のリポジトリ・別の名前にする。** このリポジトリをコピーして始め、そこから先は別のアプリとして育てる。版の番号も別々に上げる
3. **互換性は考えない。** フォントのアプリはフォント専用で、Stockroom のライブラリは開かない。今のフォントは、ファイルを書き出して新しいアプリに取り込み直す（タグ・フォルダ・評価は引き継がない）
4. **アプリの土台は共通の部品（core）にする。** 置き場所は desktop-platform。範囲はアプリの土台だけ（ウィンドウ・メニュー・設定・トースト・更新・ログ・コマンド表など、どのデスクトップアプリでも使うもの）。ライブラリや取り込み、フォルダ・タグなど「集めて整理する」仕組みは入れない
5. **順番はフォントのアプリが先、core が後。** 先にフォントのアプリを作って動かし、2 つに本当に共通している部分を見てから core に切り出す
6. **フォントのアプリが使えるようになったら、Stockroom からフォントのコードを消す**

## 決めたこと

| 論点 | 決定 |
|---|---|
| リポジトリと名前 | フォントのアプリは別のリポジトリ・別の名前。名前は **Typecase**（活字ケース。活字を種類ごとにしまう箱）。リポジトリは `hamirilo/typecase`、`identifier` は `com.local.typecase` |
| 版の番号 | Stockroom とは別々に上げる |
| ライブラリ | フォントのアプリはフォント専用。Stockroom のライブラリとの互換性は考えない |
| 今のフォント | 新しいアプリに取り込み直す。タグ・フォルダ・評価は引き継がない |
| アプリ内アップデート | 署名の鍵は Typecase 専用（Stockroom とは別）。今は本番の配布の前に替える前提の一時的な鍵（替え方は hamirilo/typecase の `docs/DEVELOPMENT.md`）。配信先は Typecase のリポジトリのリリース（リポジトリが別なので「最新」を取り合わない） |
| ブラウザ拡張・Claude（MCP） | フォントのアプリには入れない。待ち受けのポートは Stockroom の 1 つのまま |
| フォルダの共有 | フォントのアプリには入れない（最初のコピーで外す） |
| 書き出し・ライブラリ間のコピー | フォントのアプリにも残す |
| コピーした直後の片付け | フォント以外の種類（画像・ファイル・テキスト・動画・ブックマーク）、モードの仕組み、画像だけの機能を、使い始める前にまとめて消す |
| 対応する OS | macOS と Windows（Stockroom と同じ） |
| Stockroom にフォントが残ったライブラリ | 特別な扱いは作らない（使っているライブラリはもう分かれている） |
| Stockroom のフォントのコード | フォントのアプリが使えるようになったら消す。モードの仕組みも一緒に片付ける（済み。下の「Stockroom からフォントを消したとき」） |
| DB に残るフォントとモードの列 | **残して無視する**（移行で消さない）。下の「Stockroom からフォントを消したとき」 |
| core | desktop-platform に置く。アプリの土台だけ。使うのは Stockroom・フォントのアプリ・pdf-one・desktop-apps・Feedability |
| 順番 | フォントのアプリが先、core が後 |

## 詰めること

### アイコン（人が決める）

Typecase のアイコン。

### フォントのアプリ

- この端末のフォント（hamirilo/typecase の `docs/SYSTEM_FONTS.md`）は、フォントのアプリでも今の形のままでよいか
- 機能ごとの文書（`FONT_UI.md`・`SYSTEM_FONTS.md`・`MODES.md`）は Stockroom から消した。続きは hamirilo/typecase に（コピーで始めたので、そちらに同じものがある）

### core

- 何を入れるか：Stockroom・フォントのアプリ・pdf-one・desktop-apps・Feedability に共通しているものを見比べて決める
- 形：フロントエンド（npm のパッケージ）と Rust（クレート）をどう配るか。desktop-platform からの参照の仕方（git の依存、ワークスペースなど）
- 版の合わせ方：core を直したとき、各アプリにどう取り込むか

### 社内版

社内版（jazmf-dx/stockroom の `docs/CORP.md`）はもともとフォントを外しているので、影響は小さい見込み。core に切り出したあと、社内版のビルドがそのまま通るかは確かめる。

## 進め方（案）

1. Typecase のリポジトリ（`hamirilo/typecase`）を作る（人の作業）
2. このリポジトリをコピーし、フォントに要らないもの（フォント以外の種類・モードの仕組み・画像だけの機能・ブラウザ拡張・Claude・フォルダの共有）をまとめて消す
3. 今のフォントを取り込み直し、自分で使って確かめる。この間、Stockroom のフォントのモードは残しておく
4. ~~Stockroom からフォントのコードとモードの仕組みを消す~~（済み）
5. Stockroom・フォントのアプリ・ほかのアプリを見比べ、アプリの土台を core として desktop-platform に切り出す

## Stockroom からフォントを消したとき

消したもの：

- `src/features/fonts/`・`src-tauri/src/fonts/`、フォントのコマンド（見本・この端末のフォント・シェルフへの差し込みなど）
- モードの切り替え（サイドバーの［ストック｜フォント］、⌘1 / ⌘2）、モードごとのレイアウト／グループ分け／シェルフの操作、`Mode`（`lib/api.ts`・`db.rs`）
- 取り込みのフォントの形式（TTF・OTF・WOFF・WOFF2・TTC・OTC）。ほかの対応していない形式と同じように飛ばす
- Cargo の `woff2-patched`・`brotli`・`flate2`（フォントだけが使っていたもの）。SVG の文字を描く `fontdb`（resvg）と、そのフォントに欧文字があるかを見る `skrifa`（resvg と同じ版）は残す

DB は **残して無視する**。移行では列も行も消さない（古い版で開いても壊れず、移行を書かずに済む）：

| 残すもの | 扱い |
|---|---|
| `items` の `kind = 'font'` の行とファイル | 一覧・件数・検索・シェルフ・書き出し・フォルダの共有・別のライブラリへ・MCP・ゴミ箱を空にする、のどれにも出さない。ファイルもライブラリのフォルダに残る |
| `folders` / `tags` / `smart_folders` の `mode` 列 | `'stock'` のものだけを読む。新しく作るものは `'stock'`（列の既定値）。`'font'` のものは出さない |
| `tray_system` の表、`items` の `font_*` 列 | 読まない・書かない |
| ライブラリの設定の `lastMode`、「使う種類」（`modes`）の `"font"` | 読まない（`"font"` は読むときに外す） |
| アプリの設定の `sidebarHidden` | 形は前のまま（`{ "stock": [...] }`）。`stock` だけを使う |

移行の step 21 は、フォルダ・タグ・スマートフォルダをモードで分ける処理（`split_modes`）と、その前の複製（`library.before-modes.db`）をやめ、列を足すだけにした。
ライブラリ全体の書き出し（[EXPORT.md](EXPORT.md)）は、モードのフォルダの階層を無くした。
