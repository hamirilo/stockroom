# メニューの整理（メニューバー・右クリック・ツールバー）

使っていて困っていること：

- 操作の多くが右クリックとショートカットにしか無く、見つけにくい。macOS ならメニューバーにも同じ項目がほしい
- 画像の右クリックメニューが長い（回転・反転だけで 5 行。最大で 25 行ほど）
- フォルダの右クリックに中身への操作が無く、フォルダ単位で書き出せない

## 今の状態

- メニューバー：macOS のアプリメニューに「アップデートを確認…」を足しただけ（`lib.rs`）。Windows は無し
- ショートカットは `Grid.tsx` のキー処理に直接書いてあり、メニューとは別に管理している。
  ⌘J（フォルダへ移動）、⌘⇧C / ⌘⇧V（タグのコピー・貼り付け）、⇧D、⌘[ / ⌘]、⌘⌥1 / ⌘⌥2 などはどこにも書かれていない
- 右クリックメニュー（`ContextMenu.tsx`）は 1 段だけ。サブメニューは無い。特別な行は色の選択だけ
- フォルダの右クリック：サブフォルダの作成・名前の変更・色・並べ替え・削除だけ。作業台の右クリックにはある「書き出し」「まとめて出力」が無い
- 詳細パネルの下に「開く・コピー・書き出し・Finder で表示」のボタンがある

## 決定

| 論点 | 決定 |
|---|---|
| メニューバー | macOS と **Windows の両方**に出す（Windows はウインドウ上部）。中身は同じ |
| 右クリックの回転・反転、お気に入りなど | **アイコンを横 1 行に並べる**（色の選択と同じ形）。ホバーで名前とショートカットを出す |
| フォルダの書き出し | **ダイアログで選ぶ**：「サブフォルダを含める」「フォルダ構成を保つ」。初期値はどちらもオン |

## 1. コマンドを 1 か所で定義する

`src/lib/commands.ts` に、アプリの操作を 1 つずつ定義する。

```ts
interface Command {
  id: string;                 // "item.favorite"
  label: (s: State) => string; // 「お気に入りに追加」/「お気に入りから外す」
  icon?: LucideIcon;
  keys?: string;              // "F", "Mod+Shift+J"（Mod = macOS は ⌘、Windows は Ctrl）
  kinds?: ItemKind[];         // 使える種類（回転は ["image"]）
  enabled: (s: State) => boolean;
  checked?: (s: State) => boolean;
  run: (s: State) => void;
}
```

メニューバー・右クリック・詳細パネルのボタン・ショートカット・ショートカット一覧は、すべてこの定義から作る。

- 表示名とショートカットの表記がどこでも同じになる
- メニューに無い操作、メニューと違うキーが無くなる
- `Grid.tsx` のキー処理の長い if 文は、この定義を引く形に置き換える
- 種類で使えない操作（フォントやファイルの回転）は `kinds` で消す。ファイルモード（`feat/file-mode`）が入っても条件を書き足さずに済む

**ショートカットの扱い（実装時に確認すること）**

- メニューに付けたショートカットは OS が先に受け取るので、ウェブビューのキー処理には届かない。
  ⌘ 付きのキーはメニューで受け、`Grid.tsx` からは消す
- **1 文字のキー（F・P・B・Space・0〜5）はメニューのショートカットにしない**。検索欄で文字を打てなくなるため。
  今までどおりウェブビューで受け、メニューの表示名の右にキーを書くだけにする（Tauri で表示だけのショートカットが出せるか要確認。
  出せなければ表示名に添える）
- ⌘C・⌘A は入力欄でも使うので、標準の「コピー」「すべてを選択」（`PredefinedMenuItem`）にする。
  ウェブビューの `copy` などのイベントで、入力欄にフォーカスが無いときだけアイテムを扱う

## 3. 右クリックメニュー

- **見出し**：`{ header: "3 件を選択中" }`。今は各行の末尾に「（3 件）」と付けているので、上に 1 回だけ出す

- **サブメニュー**：`{ label, submenu: MenuItem[] }`。ホバーか → キーで開く

## 4. フォルダの書き出し

書き出しダイアログを新しく作る（今はフォルダを選ぶとすぐコピーする）。
ロードマップのフェーズ 3（形式の変換・リサイズ）も、このダイアログに項目を足して実現する。

```
「旅行」を書き出し
  対象：128 件（サブフォルダを含む）

  ☑ サブフォルダを含める
  ☑ フォルダ構成を保つ           書き出し先に「旅行/2025/京都/…」を作る

  書き出し先：[ ~/Desktop ]  [選ぶ…]
                                        [キャンセル] [書き出し]
```

- 「サブフォルダを含める」をオフにすると、構成の項目は灰色になる
- 「フォルダ構成を保つ」をオフにすると、すべてを書き出し先へ並べて置く（同じ名前には今と同じく連番を付ける）
- 選択中の画像を書き出すときは、構成の項目を出さない
- 1 つの画像が複数のサブフォルダに入っているときは、それぞれのフォルダへコピーする
- Rust：`export_items` に「アイテム ID → 書き出し先からの相対フォルダ」を渡せるようにする（`export_items(ids, dest, subdirs)`）。
  フォルダ名に使えない文字（`/ \ : * ? " < > |`）は `_` に置き換える
- 件数が多いときの進捗表示とキャンセルは、フェーズ 3 で並列化するときに一緒に入れる

## 5. 詳細パネル・サイドバー

- **詳細パネル**：選んだものの情報と属性（お気に入り・ピン留め・シェルフ・評価・タグ・メモ）を扱う。
  操作（回転・移動・書き出し・ゴミ箱）はツールバーへ移した（§7）
- **サイドバー**：行にホバーすると右端に「…」を出し、右クリックと同じメニューを開く。右クリックを知らなくても見つけられる

## 6. ショートカット一覧

ショートカットをすぐ確かめられる一覧画面。

### 開き方

- **?** だけ（2026-10-09 に ⌘/ をやめた。キーが 1 つのほうが覚えやすく、Gmail・GitHub などと同じ）。
  打った文字で見るので、キーボードの配列によらない。もう一度押すか Esc で閉じる
- 入力欄にフォーカスがあるときは効かない（ほかの 1 文字キーと同じ）。⌘? は macOS がヘルプの検索に使うので使わない
- ヘルプメニューの「キーボードショートカット」
- サイドバー最下部、ライブラリ名の横に小さな ⌨ ボタン（メニューバーを見ない人向け）
- ボタンのツールチップに出ているショートカットはそのまま残す

### 見た目

ウインドウ中央に出す大きめのパネル。後ろの一覧は暗くするだけで、閉じれば元の場所に戻る。

```

┌ 全体 ──────────────┐ ┌ 選択した項目 ─────────┐ ┌ ビューア ─────────────┐
│ 画像 / フォント  ⌘1 ⌘2 │ │ お気に入り         F │ │ 前 / 次       ← → A D │
│ サイドバー   Tab ⌘⌥1 │ │ 評価         0 〜 5 │ │ 全体 ⇔ 実寸         Z │
│ …                     │ │ …                   │ │ …                     │
└───────────────────┘ └──────────────────┘ └───────────────────┘

```

- キーはキーキャップの形で表示する。macOS は ⌘ ⌥ ⇧ ⌫、Windows は Ctrl Alt Shift Backspace
- 見出しごとの段組み。幅が狭ければ 2 列・1 列に折り返す
- **検索**：開いたらすぐ文字を打てる。名前（「回転」）でもキー（「⌘R」「F」）でも絞り込む
- **今いる場所を先頭に**：ビューアから開いたら「ビューア」の節を先頭に、一覧からなら「一覧」「選択した項目」を先頭に
- **今のモードに合わせる**：フォントモードでは回転を出さない、見本のレイアウトでは ⌘+ / ⌘- を「文字の大きさ」と書く。
  使えない項目は消さずに薄く表示し、「画像のみ」と添える
- 一覧から実行はしない（見るための画面）。押したキーは一覧には効かない（Esc と ? だけ受ける）

- 最初は `src/lib/shortcuts.ts` に上の表を手で書く（節・名前・キー・`kinds`・`layout` などの条件）。

## 7. ツールバー

ツールバーは今の役割（検索・絞り込み・並び順・大きさ・レイアウト）を持つ。**選択中の操作** は一覧の下に浮かぶバー（`components/SelectionBar.tsx`）に出す（2026-10 にツールバーから移した）。

```
[3 件を選択中 / 120 ✕] ｜ ♥ シェルフ ⟲ ⟳ ｜ 移動 書き出し … ｜ ゴミ箱へ
```

- よく使う操作（お気に入り・シェルフ・回転・移動・書き出し）を左に、「…」は右クリックと同じメニュー
- ゴミ箱は区切り線の右に離し、赤い文字と名前付きにして、ほかの操作を狙って押し間違えないようにした
- 回転は `appliesTo` で、画像だけを選んでいるときに出す。ゴミ箱の中では出さない（復元・削除は詳細パネル）
- ファミリー表示（フォント）では 1 行が複数のフォントを表し、選択するとそのファミリー全部が選ばれる（`Item.familyIds`、`store.ts` の `withFamilies`）

7. 詳細パネル上部の操作行（`ActionRow`）、サイドバーの行のホバーで出る「…」
8. `ARCHITECTURE.md` の「コマンド」の節

### 実装で決めたこと

- **キーの受け方**：⌘ / Ctrl 付きのキーはメニューのアクセラレータにし、一覧のキー処理（`runKey`）でも同じコマンドを引く。
  macOS はウェブビューが先にキーを受け、`preventDefault` するとメニューは動かない。Windows はメニューが先に受ける。
  どちらでも 1 回だけ動くように、キーとメニューから同じコマンドが続けて来たら後のほうを捨てる（250ms）
- **macOS の編集メニュー**：入力欄のコピー・ペーストは標準の項目（`PredefinedMenuItem`）で動くので、カット・コピー・ペースト・取り消しは標準のまま。
  メニューから「コピー」を選んだときは、ページの `copy` イベントで、入力欄にフォーカスが無ければ選択中の項目をコピーする。
  「すべてを選択」は独自の項目にし、入力欄にフォーカスがあればその文字を選ぶ
- **Windows の編集メニュー**：Ctrl+C は登録せず（入力欄のコピーを奪わないため）、表示だけ
- **表示だけのキー**（F・P・B・0〜5・Space・F2・Esc・⇧D など）：Windows はタブの後ろに右寄せで、macOS は名前の後ろに「（F）」と添える
- **詳細パネル**：お気に入り・ピン留め・シェルフは今の大きなボタン（混在の表示がある）を残し、上部の行は回転・フォルダへ移動・書き出し・「…」・ゴミ箱にした。
  下にあった「開く・コピー・書き出し・Finder で表示」は「…」のメニューへ
- **メニューの作り直し**：モード・ライブラリ・使う種類が変わったら作り直す。それ以外は名前・灰色・チェックだけを 1 フレームに 1 回反映する
