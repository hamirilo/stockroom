# 画像と動画に絞る（ファイル・テキスト・ブックマークを外す）

**決定**（2026-11-22）：Stockroom で扱う種類を **画像と動画だけ** にする。ファイル（PDF・オフィス文書）・テキスト（Markdown・テキスト・CSV）・ブックマーク（URL）は外す。
外した種類の受け皿として、**ファイル管理に絞った別のアプリ** を検討する（下の「ファイル管理のアプリ」）。

## なぜ絞るか

Stockroom の機能は、2 つに分けられる。

| | 中身 | 画像・動画 | PDF・オフィス | テキスト | ブックマーク |
|---|---|---|---|---|---|
| 見て選ぶ | 一覧のサムネイル、Pinterest 風の表示、似た画像の重複整理、比較、縦横・サイズでの絞り込み | ◎ | △ | ✕ | ✕ |
| 整理する | フォルダ、タグ、評価、検索、MCP、共有、書き出し | ○ | ○ | ○ | ○ |

- Stockroom の強みは「見た目で探して選ぶ」こと。これが活きるのは画像と動画だけ
- PDF・オフィス：サムネイルは 1 ページ目かファイルに埋め込まれたプレビューで、文書はどれも同じに見える。オフィス文書は種類のカードになることもある
- テキスト：サムネイルは本文の先頭を紙のように描いたもので、どれも似た見た目になる。探すときは検索欄に頼る。
  編集の機能を増やすとエディタになっていき、「取り込んだ元ファイルは書き換えない」の例外も広がる
- ブックマーク：ファビコンやアイキャッチは、そのページを見分ける手がかりになりにくい。まだ決めていなかったこと（リンク切れの確認、保存したあとの更新、ページの中身の保存）は、どれもブラウザか通信が要る。ブラウザとつながる Web アプリの方が向いている
- 「整理する」機能だけなら、Finder やエディタ、ブラウザでも足りる

種類が混ざることへの手当ても要らなくなる：ファイルだけのときのグリッドとリストへの切り替え、縦横の条件を外す処理（`fitToKinds`）、種類ごとのビューア。
[UI.md](UI.md) の「切り替えても操作の位置を変えない」を守る手間も減る（フォントを分けたとき（[FONT_APP.md](FONT_APP.md)）と同じ構図）。

## 決めたこと

| 論点 | 決定 |
|---|---|
| 扱う種類 | 画像と動画（`KINDS`、`db::Kind`） |
| 消す時期 | **すぐに消す**。ファイル管理のアプリができるのは待たない。それまでは、外した種類は Stockroom の外（Finder など）で扱う |
| ライブラリに残っている項目 | **消す**（ゴミ箱の中のものも）。ライブラリを開いたときに、行と、ライブラリの中のファイル（元のファイル・サムネイル・プレビュー）を消す。元に戻せない。下の「残っている項目を消す」 |
| 取り込み | ファイル・テキスト・ブックマークの形式は、対応していない形式と同じように飛ばす |
| ブラウザ拡張 | 「このページをブックマークに保存」を外す。画像の保存はそのまま |
| ほかのアプリから受け取る（[FROM_APPS.md](FROM_APPS.md)） | **Stockroom では受けない**。`POST /bookmark` を外し、Feedability の記事（`.md`）は対応していない形式として断る。あとでアプリからの接続そのものもやめた（下の「あとで決めたこと」）。ファイル管理のアプリで受けるかは、そのアプリを検討するときに決める |
| フォントの行 | 今回は触らない（今どおり残して読まない。`NOT_FONT`） |
| 機能を絞ったビルド（[LIMITS.md](LIMITS.md)） | `STOCKROOM_KINDS` は残す。選べるのは `image` と `video` |

## あとで決めたこと（2026-11-22、v1.0 の前）

| 論点 | 決定 |
|---|---|
| 種類で絞る | 2 種類になったので、メニューをやめて［画像｜動画］のセグメントにする。⌘クリックで重ねて選ぶのはやめる（[KINDS.md](KINDS.md)） |
| ほかのアプリとの接続 | **やめる**。受付は拡張機能だけ。保存（POST）は拡張機能の `Origin` が付いたものだけを受け付け、前に接続したアプリも保存できなくする（[FROM_APPS.md](FROM_APPS.md)） |
| 縦横の条件を外す処理 | 画像と動画しかないので外す（`fitToKinds`・`listHasPixels`・並び替えの `only`） |
| 版 | ここまでを入れて v1.0.0 とする。先に出した v1.0.0（この節の前まで）は取り下げて出し直す |

## 残っている項目を消す

- ライブラリを開くたびに、種類が画像・動画・フォント以外の行（`file` / `text` / `bookmark`）を探して、あれば消す（`db::leftover_kinds`、`Library::open`）。
  移行のステップにはしない（古い版で開いて足されたものも、次に開いたときに消える）
- 消し方は「ゴミ箱を空にする」と同じ（`delete_items` → `remove_files`）。シェルフからも外れる。親子の紐づけは子の側が外れる（`ON DELETE SET NULL`）
- 消したことはログに残す（件数）

## ファイル管理のアプリ

これから検討する。決まったことはここに足すか、そのアプリのリポジトリに移す。

検討すること：

- 何を扱うか：PDF・オフィス文書・テキスト・ブックマークのどれを入れるか。ブックマークは Web アプリの方が向いているので、別にするか
- 「見て選ぶ」が活きない種類で、何を強みにするか（中身での検索、ファイルの名前・場所の整理、外部アプリとの行き来など）
- Feedability の記事とリンクを受けるか
- アプリの土台：desktop-platform の共通の部品を使う（[FONT_APP.md](FONT_APP.md) の「方針」4）
- Stockroom から外したコード（`files/`・`texts/`・`bookmarks/`。消す前の版は git の履歴にある）を出発点にするか

外したときに消した文書（`docs/TEXT.md`・`docs/BOOKMARKS.md`）も git の履歴にある。テキストの文字コード（Shift_JIS の CSV）や、ブックマークの URL のそろえ方・重複の扱いなど、決めてあったことはそこを見る。

## 外したもの（コード）

- Rust：`files/`（Quick Look・Windows.Data.Pdf・Office の PDF 変換・中のプレビュー）、`texts/`、`bookmarks/`、`POST /bookmark`、`set_text`・`files_of_types`、検索の本文（`items.body`）。
  依存の `encoding_rs`・`zip`、`windows` の `Data_Pdf`・`Storage_Streams`
- 動画のサムネイルが使っていた Quick Look と種類のカードは `videos/frame.rs` に移した
- 画面：`features/files/`・`features/texts/`・`features/bookmarks/`、新規テキスト（⌘N）、文字・URL の貼り付け、種類のチップの PDF・表計算などの色、`marked`
- ブラウザ拡張：「このページをブックマークに保存」（右クリックとポップアップ）
- iWork のパッケージ（フォルダ）の中身を取り込まない処理は残した（中のプレビュー画像を画像として取り込まないように）
