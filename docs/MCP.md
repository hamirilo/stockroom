# Claude からの整理（MCP サーバー）

やりたいこと：

- ファイル名に含まれる文字から、タグを付けたりフォルダに分けたりする（命名規則がばらばらでも、意味で読み取ってほしい）
- 表示名をそろえる（日付・連番・商品コードなどの書き方を統一する）
- 少ない枚数なら、画像を見て分類・タグ付けしてもらう

**実装済み**（`src-tauri/src/mcp/`、`changes.rs`、`loopback.rs`、`src/components/ClaudeSettings.tsx`）。

アプリに AI を組み込むのではなく、**アプリが MCP サーバーになり、ユーザーが普段使っている Claude（Claude Code / Claude Desktop）から操作する**。
アプリは API キーを持たず、使用量はユーザーの Claude のプランから出る。ロードマップの「AI 以外」という方針とぶつからない。

## 決定

| 論点 | 決定 |
|---|---|
| どこで動かすか | **アプリの中**（受付サーバー `webimport.rs` と同じく 127.0.0.1 で待ち受ける）。アプリを開いている間だけ使える |
| DB に書き込むのは | **アプリだけ**。別プロセスから `library.db` を直接開かない（同時書き込みと UI の更新漏れを避ける） |
| 対象のライブラリ | **いま開いているライブラリ**。ライブラリを切り替える操作は出さない |
| 出す操作 | 読み取り、タグ、フォルダ、表示名、メモまで。**削除・ゴミ箱・取り込み・書き出しは出さない** |
| 変更の取り消し | MCP からの変更を **まとめ単位で記録し、アプリから元に戻せる**ようにする |
| 初期状態 | **オフ**。設定でオンにしたときだけ待ち受ける |

## つなぎ方

```
Claude Code ──(HTTP)────────────────────────┐
                                             ├─▶ アプリ内の MCP サーバー 127.0.0.1:41621/mcp ─▶ library.db
Claude Desktop ─(stdio)─▶ stockroom --mcp ─────┘     （トークンで認証）
                         （中継するだけ）
```

### アプリ内の MCP サーバー

- 方式は MCP の **Streamable HTTP**。エンドポイントは `POST /mcp` の 1 つ。応答は `application/json` で返し、SSE は使わない
  （サーバーから通知を送る必要が無いため。`GET /mcp` には 405 を返す）
- 対応するメソッド：`initialize`、`notifications/initialized`、`ping`、`tools/list`、`tools/call`。
  必要なのはこれだけなので、JSON-RPC は `tiny_http` の上に自前で書く（`rmcp` などを入れると tokio / axum の依存が増える割に、使う部分が少ない）。
  待ち受けと停止の処理は受付サーバーと共通（`loopback.rs`）
- ポートは **41621**（受付サーバーの 41620 の隣）
- 受付サーバーとはサーバーもトークンも分ける。許すことが違う（向こうは取り込みだけ、こちらは整理）ので、片方だけオンにできるようにする
- 安全策は受付サーバーと同じ：
  - ループバックだけで待ち受ける
  - `Authorization: Bearer <token>` が必須
  - `Host` が 127.0.0.1 / localhost 以外なら拒否する（DNS リバインディング対策）
  - `Origin` ヘッダーが付いていたら拒否する（MCP クライアントは付けない。付くのは Web ページからのリクエスト）
- テストで Tauri 無しに動かせるよう、`webimport.rs` の `Host` と同じ形のトレイトを挟む

### Claude Code から

HTTP の MCP サーバーとしてそのまま登録できる。設定画面に、このコマンドを丸ごとコピーするボタンを置く。

```bash
claude mcp add --scope user --transport http stockroom http://127.0.0.1:41621/mcp --header "Authorization: Bearer <token>"
```

### Claude Desktop から（中継）

Claude Desktop のローカル設定（`claude_desktop_config.json`）は stdio のサーバーしか起動できない。
そこで、**アプリ本体を `--mcp` 付きで起動すると、stdio と HTTP を中継するだけのプログラムとして動く**ようにする（別のバイナリは配らない）。

```json
{
  "mcpServers": {
    "stockroom": {
      "command": "/Applications/Stockroom.app/Contents/MacOS/stockroom",
      "args": ["--mcp"]
    }
  }
}
```

- `main.rs` で引数を見て、`--mcp` があれば Tauri を起動せずに中継を始める
- トークンは `settings.json`（`app_config_dir`）から読む。設定ファイルにトークンを書かずに済む
- アプリが開いていないとき：`initialize` には答え、ツールを呼ばれたら「Stockroom を開いてから、もう一度試してください」というエラーを返す
- 設定画面に、上の JSON を丸ごとコピーするボタンを置く（パスは実行中のアプリの場所 `current_exe` から作る）
- `tools/call` 以外（`initialize`、`tools/list`）は中継が自分で答える。アプリを閉じていても Claude Desktop は起動でき、ツールを使ったときに「開いてください」と返る

## ツール

すべてのツールに MCP のヒントを付ける（読み取りは `readOnlyHint: true`、書き込みは `destructiveHint: false`）。
Claude Code / Claude Desktop では、書き込みのたびにユーザーの承認が入る。

### 読み取り

| ツール | 引数 | 返すもの |
|---|---|---|
| `library_info` | なし | ライブラリの名前、使っている種類と件数、タグなし・未分類の件数、フォルダとタグの数（フォント用の数も） |
| `list_folders` | `kind?` | フォルダをパス（`写真/旅行/京都`）と件数で。フォント用は「（フォント用）」の見出しの後に続く。`kind` を付けるとその種類用だけ |
| `list_tags` | `kind?` | タグ名と件数。フォント用は「（フォント用）」の見出しの後に続く |
| `find_items` | `where`（下の「絞り込み」）、`limit`（初期値 200、最大 1000）、`offset` | 表示名の順に 1 件 1 行：短い id、種類、表示名、フォルダのパス、タグ、取り込み元 URL、メモの先頭。先頭に全体の件数。親子の紐づけが有効なライブラリでは、最後に「親」（子の親の短い id）と「採用」の列が付く |
| `view_images` | `ids`（最大 10 件）、`max_side`（初期値 512、最大 768） | 縮小した画像（MCP の image コンテンツ）と、それぞれの id・表示名 |

**絞り込み `where`**（`find_items` と書き込みで共通。知らないキーはエラーにする）

- `kind`：`image` / `font` / `file` / `text` / `video` / `bookmark`
- `folder`：フォルダのパス。`include_subfolders` でサブフォルダも含める
- `tags`：タグ名のリスト。`tag_match_all` を付けるとすべて付いているもの
- `untagged` / `unfiled`：タグなし／未分類だけ
- `name_contains`：表示名にこの文字を含む（大文字・小文字は区別しない）。ファイル名からの整理はほぼこれで足りる
- `search`：一覧の検索と同じ（`ItemQuery.search`。表示名・メモ・タグ名・フォント名・テキストの本文が対象）
- `ext`：拡張子

中身は `db::query_items` の `ItemQuery` に変換し、`View` に入りきらない条件（フォルダ指定とタグなしの組み合わせ、`name_contains`）は後から絞る。
ゴミ箱の中は含めない。フォルダやタグの名前が無ければ、空の結果ではなくエラーにする（Claude が書き間違いに気づけるように）。

フォルダ・タグ・スマートフォルダは、画像・ファイル・テキスト用（ストック）とフォント用で別々（docs/MODES.md）。同じパス・同じ名前が両方にあることがある。
`folder` と `tags` はモードごとに引き、両方の結果を合わせて返す（`kind` を付ければそのモードだけ）。

**トークンを減らす工夫**

- 返すのは JSON ではなく、タブ区切りの行にする（キー名を毎行繰り返さない）
- id は UUID の **先頭 8 文字** で返す。書き込みのときは 8 文字以上の先頭部分を受け付け、
  サーバーが一意に引き当てる（同じ先頭を持つものが複数あればエラーにする）
- フォルダとタグは id ではなく名前で返し、名前で受け付ける（Claude がそのまま読み書きできる）

### 書き込み

対象の指定は **`ids`（id のリスト）か `where`（上の絞り込み）のどちらか**。
「名前に kyoto を含むものすべてに『京都』を付ける」のような規則的な変更なら、
Claude が一覧を読まなくても `where` で一度に済み、トークンを使わない。

| ツール | 引数 | 内容 |
|---|---|---|
| `add_tags` | 対象、`tags` ／ または `[{id, tags}]` | タグを付ける。無いタグは作る。各アイテムには、そのモード（フォントかそれ以外か）の同じ名前のタグが付く |
| `remove_tags` | 対象、`tags` ／ または `[{id, tags}]` | タグを外す（タグ自体は消さない） |
| `create_folder` | `path`（`写真/旅行/京都`）、`kind?` | 途中のフォルダもまとめて作る。既にあれば何もしない。`kind: font` でフォント用（既定は画像・ファイル・テキスト用） |
| `move_to_folder` | 対象、`folder`（パス） | フォルダへ移す（アイテムが入れるフォルダは 1 つまで）。各アイテムはそのモードの同じパスのフォルダへ入る |
| `remove_from_folder` | 対象 | 未分類に戻す |
| `rename_items` | `[{id, name}]` | 表示名を変える |
| `set_note` | `[{id, note}]` | メモを書き換える |
| `link_items` | `parent`（id）、対象 | 対象を `parent` の子として紐づける（子は親のフォルダへ移る）。親子の紐づけが有効なライブラリだけ（[LINKS.md](LINKS.md)）。親そのもの・子を持つ項目・ストック以外・ゴミ箱の中のもの、親が子のときは紐づけず、件数で知らせる |
| `unlink_items` | 対象 | 紐づけを外す（ふつうの項目に戻り、いまのフォルダに残る）。親を指定するとその子すべて |
| `set_adopted` | `id`（子）、`adopted?`（既定 true） | 子の 1 つを採用にする（親ごとに 1 つ。ほかの子の採用は外れる） |

**共通のルール**

- 1 回で変えられるのは **500 件まで**。超えたら、何も変えずにエラーを返す（Claude に分けて呼んでもらう）
- 1 回の呼び出しは 1 つのトランザクション。途中で 1 件でもエラーになれば、何も変えない
- `dry_run: true` を付けると、同じ処理をトランザクションの中で実行して巻き戻す（結果は本番と同じになる）：
  「【試し実行・まだ変えていません】タグを付けました（「京都」4 件、「東京」2 件）」
- 結果には、変えた件数・変えなかった件数とその理由・取り消し用の **変更番号** を入れる
- 何も変わらなかったときは記録しない（「変更はありません。」）

**表示名の変更（`rename_items`）**

- 変わるのは表示名（`items.name`）だけ。ライブラリの中の実ファイル（`file_name`）はそのまま
- 表示名は書き出しのときのファイル名になる（`export_target`）。ここをそろえれば、書き出したファイル名もそろう
- 拡張子は変えさせない：新しい名前に拡張子が無ければ元の拡張子を足し、違う拡張子が付いていたらエラーにする
- 空の名前、`/` などファイル名に使えない文字を含む名前はエラーにする

## 変更の記録と取り消し

今の「元に戻す」は、フロントエンドの操作ごとのトースト（`lib/actions.ts`）が持っている。
MCP からの変更はバックエンドで直接行うので、この仕組みに乗らない。そこで、バックエンドに記録を持たせる。

### データ

`library.db` に追加する。他のテーブルと同じく `CREATE TABLE IF NOT EXISTS` で作る。

```sql
CREATE TABLE IF NOT EXISTS changes (
  id        INTEGER PRIMARY KEY,
  at        INTEGER NOT NULL,   -- ms
  source    TEXT NOT NULL,      -- "mcp"（ほかの経路でも使えるように）
  summary   TEXT NOT NULL,      -- 「120 件に『京都』を付けました」
  undo      TEXT NOT NULL,      -- JSON：元に戻すための操作
  undone_at INTEGER
);
```

- `undo` には、実際に変わったものだけを入れる
  - タグ：新しく付いた (item, tag) の組 ／ 外れた組
  - フォルダ：各アイテムの移す前のフォルダと並び順（`item_folders.position`）
  - 表示名・メモ：前の値と後の値
  - フォルダの作成：作ったフォルダの id
- 残すのは新しいものから 100 件。ライブラリと一緒に持ち運べるよう、メモリではなく DB に置く
  （Claude に頼んだ翌日に「やっぱり戻したい」となっても戻せる）

### 元に戻す

- 戻すのは、**今の値が「後の値」のままのものだけ**。その後に手で変えたものは触らず、
  「8 件はその後に変更されていたため、そのままにしました」と知らせる
- 作ったフォルダは、空のときだけ消す
- ツールとしては出さない（取り消しはユーザーがアプリでする操作。Claude が自分の変更を勝手に消さないように）

### UI

- 書き込みのたびに、バックエンドからイベント `library-changed` を送る。フロントエンドは一覧・件数・サイドバーを読み直す
  （受付サーバーの `web-import` と同じ流れ）
- トーストを出す：「Claude：タグを付けました（「京都」4 件） ［元に戻す］」。1.5 秒以内に続いたものは 1 つのトーストにまとめ、
  ［元に戻す］でまとめて（新しい順に）戻す
- 「Claude と連携」の設定に、最近の変更（30 件）の一覧を置き、そこからも戻せるようにする（トーストを見逃したとき用）

## 設定

設定画面（`SETTINGS.md`）の「連携」タブに、ブラウザ拡張と並べて置く。設定画面ができるまでは、
設定画面（⌘,）の「連携」タブ、ブラウザ拡張の下に置く（メニューバーの「ヘルプ > Claude と連携…」からも開く）。

- 「Claude からの整理を許可する」（オン／オフ）と、待ち受けの状態（起動中／エラーの理由）
- 「Claude Code 用のコマンドをコピー」「Claude Desktop 用の設定をコピー」
- 「トークンを作り直す」（つないでいた Claude からは使えなくなる、と添える）
- 最近の変更（上の「UI」）

`settings.json` の `Settings` に、受付サーバーの `web_import` と同じ形で `mcp: { enabled, token }` を足す。

## どのくらい使うか（目安）

| やること | 1 件あたり | 例 |
|---|---|---|
| 一覧を読む（`find_items`） | 30〜50 トークン | 1,000 件で 3〜5 万 |
| 規則で一括変更（`where`） | ほぼ 0 | 件数によらず 1 回の呼び出し |
| 1 件ずつの変更（`[{id, ...}]`） | 20〜40 トークン | 500 件で 1〜2 万 |
| 画像を見る（512px） | 約 350 トークン | 30 枚で約 1 万 |
| 画像を見る（768px） | 約 800 トークン | 30 枚で約 2.5 万 |

画像を見る使い方は「このフォルダの 30 枚」くらいの規模を想定する。数千枚を一度に見るのは、時間も使用量も現実的でない。

## 使い方の例

- 「タグなしの画像を一覧して、ファイル名から付けられそうなタグを提案して。良さそうなら付けて」
- 「`IMG_` で始まる名前を、撮影日の部分を使って `2023-05-12_京都_01` の形にそろえて。先に 10 件だけ案を見せて」
- 「『未整理』フォルダの中身を、名前から判断して `写真/旅行/<地名>` に分けて」
- 「『素材』フォルダの 20 枚を見て、写真・イラスト・アイコンのタグを付けて」

## 作らないもの

- 削除・ゴミ箱へ入れる操作：間違えたときの影響が大きい。重複の整理はアプリの「重複の候補」で行う
- 取り込み・書き出し：ファイルシステムに触れる操作は出さない
- ライブラリの切り替え・作成
- 評価・お気に入り・ピン留めの変更：「整理」の目的からは外れる。要望があれば足す
- アプリ内での AI の呼び出し（API キーを持つ方式）

## 後で足す候補

- `merge_tags`：表記ゆれ（「猫」「ねこ」「cat」）を 1 つにまとめる。付け替えたあとに古いタグを消すので、取り消しの記録に「消したタグ」も入れる
- `rename_tag`、`set_tag_color`
- `create_smart_folder`：言葉で頼まれた条件をルールに直して保存する
- フォントの見本画像を返す（`view_images` をフォントにも使う。サムネイルで足りるかを試してから）
- ファイル（PDF など）から中の文字を返す

## 試し方（開発）

```bash
cargo run --manifest-path src-tauri/Cargo.toml --example mcpserver -- /path/to/Test.library
```

`-- <library> 41699` のように別のポートを指定する。
